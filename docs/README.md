## Core Principles

OctoAcme project management is built on these foundational principles:

- **Customer-first**: Prioritize customer value and usability in every decision
- **Iterative delivery**: Deliver small, testable increments to validate assumptions early
- **Clear ownership**: Each project has named owners with explicit roles and responsibilities
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback, learning, and blameless problem-solving

## Project Lifecycle Overview

OctoAcme projects follow a five-phase lifecycle designed to maximize clarity, reduce risk, and enable continuous learning:

```
┌─────────────┬─────────────┬──────────────┬───────────────┬──────────────┐
│ Initiation  │  Planning   │  Execution   │   Release     │ Retrospective│
├─────────────┼─────────────┼──────────────┼───────────────┼──────────────┤
│ • Problem   │ • Scope &   │ • Daily      │ • Deploy to   │ • Capture    │
│   statement │   backlog   │   standups   │   staging &   │   learnings  │
│ • Business  │ • Timeline  │ • PR reviews │   production  │ • Identify   │
│   need      │ • DoD       │ • Testing    │ • Post-deploy │   improvements
│ • Success   │ • Risks &   │ • Tracking   │   verification│ • Action items
│   metrics   │   deps      │ • Demos      │ • Announce    │ • Celebrate  │
└─────────────┴─────────────┴──────────────┴───────────────┴──────────────┘
```

### Phase 1: Initiation
Define the problem, validate business need, align stakeholders, and make a go/no-go decision. Output: Project One-pager with success metrics and stakeholder list.

### Phase 2: Planning
Break work into actionable increments, estimate scope, define acceptance criteria, and create a release plan. Output: Prioritized backlog, release timeline, and risk register.

### Phase 3: Execution
Deliver incrementally through daily standups, code reviews, testing, and risk tracking. Output: Working software, validated features, updated project status.

### Phase 4: Release
Deploy to production with confidence through pre-release checks, deployment procedures, and post-deploy verification. Output: Released feature, release notes, and rollback plan if needed.

### Phase 5: Retrospective
Capture learnings, identify improvements, and feed insights back into processes. Output: Action items, process improvements, and knowledge artifacts.

## Key Roles

### Project Manager
- **Focus**: Coordinates delivery, manages schedules, risks, and communications
- **Key Responsibilities**: Create project plans, manage risks and dependencies, facilitate meetings, maintain documentation
- **Success**: Deliver on time, minimize escalations, maintain transparency

### Product Manager
- **Focus**: Defines what should be built and measures business impact
- **Key Responsibilities**: Define problem statements, prioritize backlog, validate solutions, measure outcomes
- **Success**: Maximize customer value, make data-driven decisions, ensure product-market fit

### Developers
- **Focus**: Design, build, test, and deliver software components
- **Key Responsibilities**: Implement features, write tests, participate in code reviews, identify technical risks
- **Success**: Deliver reliable code, reduce cycle time, maintain high quality

### QA/Testing
- **Focus**: Validates quality and ensures acceptance criteria are met
- **Key Responsibilities**: Create test plans, execute tests, validate acceptance criteria, identify quality issues
- **Success**: Catch defects early, validate feature quality, reduce production issues

### Stakeholders
- **Focus**: Provide inputs, guidance, and approvals
- **Key Responsibilities**: Provide requirements, review progress, approve decisions, support team
- **Success**: Projects align with business needs, stakeholders stay informed

## Key Artifacts

Every OctoAcme project maintains these core artifacts:

- **Project Charter / One-pager**: Problem statement, success metrics, stakeholders, timeline
- **Roadmap & Release Plan**: High-level plan showing milestones and delivery dates
- **Sprint / Iteration Backlog**: Prioritized list of work items with acceptance criteria
- **Definition of Done (DoD)**: Explicit criteria for what "done" means (tests, documentation, review)
- **Risk Register**: Tracked risks with impact, likelihood, mitigation, and owners
- **Release Notes**: Summary of changes, migration steps, known issues
- **Retrospective Notes**: Learnings and action items with owners and due dates

## Communication Cadence

Effective communication keeps teams aligned and stakeholders informed:

- **Daily Standups**: 15-minute team syncs on progress, blockers, dependencies
- **Weekly PM/PdM Sync**: Alignment on roadmap, priorities, risks
- **Twice-Weekly Team Sync**: Deeper execution sync for delivery teams
- **Weekly Status Updates**: Stakeholder communication on progress and risks
- **Monthly Executive Updates**: High-level business impact and milestones
- **Ad-hoc Escalations**: Immediate communication for blockers or critical issues

## Getting Started Checklist

If you're starting a new project at OctoAcme, here's a quick checklist:

- [ ] **Initiation**: Complete Project One-pager and get stakeholder alignment
- [ ] **Planning**: Create backlog, estimate, and define release milestones
- [ ] **Setup**: Create project board and repository with this documentation
- [ ] **Team**: Assign Project Manager, Product Manager, and team members
- [ ] **Communication**: Schedule recurring standups, syncs, and status updates
- [ ] **Execution**: Begin sprints with daily standups and PR reviews
- [ ] **Release**: Prepare deployment checklist and release notes
- [ ] **Retrospective**: Schedule and run retrospective after first release
